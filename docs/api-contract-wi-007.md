## Overview

This contract specifies the API endpoint for downloading a pre-formatted Excel template file for invoice intake. The template contains the correct column headers matching the validation allowlist defined in `ExcelParsingService.ALLOWED_COLUMN_NAMES`, so users can fill in their invoice data in the expected format before uploading via the Excel upload endpoint (`POST /api/v1/intake/excel`, contract `docs/api-contract-wi-002.md`).

## GET /intake/excel/template

### Description

Download a pre-formatted Excel template file for invoice intake. The template contains five column headers matching the backend validation allowlist. The template is empty (no example data) with one empty data row as a visual guide.

### Request

**Method**: `GET`
**Path**: `/api/v1/intake/excel/template`
**Authentication**: None (MVP, per D-020)
**Query Parameters**: None
**Request Body**: None

### Response — 200 OK (Template Download)

**Content-Type**: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
**Content-Disposition**: `attachment; filename="invoice-intake-template.xlsx"`

Binary response: a valid `.xlsx` Excel file generated by Apache POI with the following structure:

| Row | Column A | Column B | Column C | Column D | Column E |
|-----|----------|----------|----------|----------|----------|
| 0 (header) | `invoice number` | `debtor name` | `address` | `phone number` | `bank account number` |
| 1 (empty) | | | | | |

**Template file constraints:**

| Constraint | Detail |
|-----------|--------|
| Format | Valid Apache POI-generated XLSX file |
| Column headers | Row 0 (first row), columns A through E (indices 0-4) |
| Header values | `invoice number`, `debtor name`, `address`, `phone number`, `bank account number` |
| Header case | Case-sensitive, exact match against `ExcelParsingService.ALLOWED_COLUMN_NAMES` |
| Data rows | At least one empty data row (row 1) as visual guide |
| Data validation | No data validation rules or dropdown lists |
| Formatting | No formatting beyond standard headers |
| Example data | Empty (no example data) |
| File size | < 100KB |

**Implementation constraint**: Column headers must be defined as constants referencing `ExcelParsingService.ALLOWED_COLUMN_NAMES` to prevent drift from the validation allowlist (D-029).

### Response — 500 Internal Server Error

**Content-Type**: `application/json`

```json
{
  "status": "INTERNAL_ERROR",
  "errorDetail": "Template generation failed"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `status` | string | `"INTERNAL_ERROR"` |
| `errorDetail` | string | Human-readable error description. Must not expose server internals (stack traces, file paths, directory structure). |

### Error Mapping Registry

| Internal Error | API Response | Description |
|----------------|--------------|-------------|
| `IOException` (template write failure) | 500 Internal Server Error | Template generation failed |

## Integration Notes

### Template Generation

Template generation should reside in `ExcelParsingService` as a new public method (e.g., `generateTemplateXlsx()`), following the existing pattern of [`generateReturnXlsx()`](5-backend/business-service/src/main/java/com/gimmevettingsolution/intake/service/ExcelParsingService.java:516). The method must:

1. Create an `XSSFWorkbook` via Apache POI
2. Create a single sheet
3. Write the five column headers to row 0 using constants from `ALLOWED_COLUMN_NAMES`
4. Create one empty data row at index 1
5. Return the result as a `byte[]` or write to an `OutputStream`

### Controller Endpoint

The endpoint should be added to [`ExcelIntakeController`](5-backend/business-service/src/main/java/com/gimmevettingsolution/intake/ExcelIntakeController.java) at mapping `/api/v1/intake/excel/template`, returning the template bytes with the response headers specified above.

### Column Header Consistency

The template headers must exactly match the values in [`ExcelParsingService.ALLOWED_COLUMN_NAMES`](5-backend/business-service/src/main/java/com/gimmevettingsolution/intake/service/ExcelParsingService.java:28):

```java
private static final Set<String> ALLOWED_COLUMN_NAMES = Set.of(
    "invoice number",
    "debtor name",
    "address",
    "phone number",
    "bank account number"
);
```

The template generation method must reference these constants directly, not duplicate the strings.
